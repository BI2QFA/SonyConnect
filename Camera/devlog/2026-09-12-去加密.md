# 2026-09-12 去加密：双端删掉全部加解密

**起因**：上一轮性能返工后，用户判断瓶颈是加密，要求"双端所有的加密算法全部去掉，
包括文件传输和数据接口，只保留应有的功能"。

同时用户说明**读不到相机端日志**。核查结果比"读不到"更糟：

> `PairingStore.setLog()` / `PtpCameraHandler.setLog()` **全工程没有任何调用点**。
> 也就是说日志出口永远是 null，`logLine`/`tryLog` 一辈子都是空操作 ——
> 上一轮我加进去的"传输耗时 / MB/s / 配对预派生耗时"日志**根本写不出来**。
> 让用户去读一份不存在的日志是我的错。日志实现按用户要求整体删除。

## 一、删掉了什么

**相机端**

| 删除项 | 说明 |
|---|---|
| `CryptoSuite.java` | 整个文件：AES-128-CBC + HMAC-SHA256、EtM 封包、会话密钥派生、PBKDF2 |
| 加密帧层 | `sealFrame` ×2 / `openFrame` / `Frame` / `ENC_HDR_LEN`；帧不再有 TxId/Seq/密文/MAC 头 |
| 四步双向认证 | `authenticate()` 与 `OP_AUTH_CHALLENGE/RESPONSE`（0x9010/0x9011） |
| 配对密钥协商 | `pairingSalt` / `pairingKey` / 窗口期 K_pair 预派生 / `PAIR_COMMIT` / `PAIR_KDF_ITERATIONS` / `TAG_PAIR_*` |
| 配对表密钥字段 | `sharedKey` / `cryptoSuite` / `encryptData` 及其落盘字段 `key/suite/enc` |
| 连接级序号与密码器 | `Conn.session` / `encStream` / `seqOut` / `seqIn`（`authed`→`authorized`） |
| 日志实现 | `Handler.onLog` / `PairingStore.Log` / `setLog` / `logLine` + 全部 89 处调用点 |
| 常量改名 | `FAIL_CRYPTO_REQUIRED` → `FAIL_NOT_PAIRED`（语义由"要加密"变成"先配对"） |

**手机端**

| 删除项 | 说明 |
|---|---|
| `crypto/SessionCrypto.kt` | 整个文件（含上轮刚做的 `Stream` 复用密码器） |
| `crypto/KeyDerivation.kt` | 整个文件（hmac/pbkdf2/session/aad/le64/eqConst…） |
| `PtpIpClient` 的会话与认证 | `psk` 参数、`session`、`finishAuth`、`authenticate`、`sessionCrypto`、`PtpAuthException`、`sendFramed`/`openFrame`/`sealFrame` |
| `Link` 的序号与密码器 | `seqOut` / `seqIn` / `resetSeq` / `session`；`sendRaw`/`sendFramed` 合并为 `send` |
| 配对表密钥字段 | `sharedKey` / `cryptoSuite` / `encryptData` + Base64 编解码 |
| 数据通道加密 | `DataChannel` 的 `session` 参数与逐帧解密 |

`CryptoSuite.random` / `KeyDerivation.random` 保留下来，改名成两端的 `Rand`（设备码、
配对码必须是不可预测的随机值，这与加解密无关）。

## 二、现在的协议长什么样

**帧**：`Length(4) | Type(4) | 载荷` —— 就是 `PtpCodec` 造好的明文帧，链路上再无封装层。
没有序号空间（到达顺序由 TCP 保证），没有 MAC，没有重放防护。

**连接流程**（相机端 `serveControl`）：

```
TCP → Init Cmd Req
  ├─ 该手机在配对表里？ → Init Cmd Ack → 直接进控制循环
  └─ 不在，且配对窗口开着 → Init Cmd Ack → 配对两步 → 落表 → 同一连接进控制循环
     不在，窗口也没开 → Init Fail(NOT_PAIRED) 断开
```

**准入判定只有这一处**：查配对表。这是"强制配对"从加密时代留下的语义，也是现在
唯一的门 —— 去掉了认证之后，"在不在表里"就是全部。

**配对两步**（全程明文）：

```
① PAIR_BEGIN    req blob = 手机设备名(UTF-8)      rsp blob = devIdC(8)
② PAIR_EXCHANGE req blob = 6 位配对码(ASCII)      rsp      = RC_OK / RC_PAIRING_FAILED
```

相机端在处理 ② 时**先落表、再回 OK**（回包意味着"我已存好"），手机端不需要重连。
窗口/6 位码/5 次失败关窗/180s 有效期这些行为一字未改。

**文件通道**：`DATA_OPEN` → `DATA_OPEN_ACK` → `Start Data` → `Data*` → `End Data`，
全部明文。一次性令牌（绑设备 + 用后即废 + 15s TTL）与"必须找得到该设备已获准的
控制会话"这两道检查都保留 —— 令牌是取件凭据，准入仍然只在控制连接上判一次。

## 三、一字未改的功能面（用户最关心的部分）

配对模式页与 6 位码、失败计数、设备码持久化、目录浏览、缩略图（160×120）、
大预览（1616×1080）、原图与 offset/length 断点续传、缩略图队列（begin/pause/resume/
cancel）、事件推送、遥控退出（EXIT_APP + 有序退出链）、UDP 发现（含配对状态回报）、
单客户端语义（同设备踢旧 / 他设备 BUSY 且不打断传输）、配对表持久化。

上一轮的**性能改动全部保留**：传输期持久文件句柄（整段只 open 一次 SD 文件）、
128 KiB 分块、单次拷贝封包、收包零拷贝（区间解密那部分随加密一起去掉了，区间写盘保留）、
发现的已知地址快扫 + 候选端口一次全打 + 静默早退。

## 四、安全影响（明说，不粉饰）

- **链路内容明文**：控制面与文件面都是。同网段任何人都能抓包看到照片与文件名。
- **配对码明文过网**：它不再有密码学保护，作用退化为"证明操作者看得到相机屏上那个码"。
  6 位数字在明文链路上是可被嗅探的。
- **无重放防护**：原先靠加密帧序号拦截重放，现在没有这层。
- **准入仍然强制**：未配对设备一律 `Init Fail(NOT_PAIRED)`，这一条没有放松；
  配对表仍是唯一的门。但"配对过"不再意味着链路私密。
- **回退路径**：加密版完整保存在 git 里（上一个提交），要恢复就 checkout 那一个提交。

适用判断（留给用户）：这是两台设备之间的点对点 Wi-Fi（热点/Direct），传输对象是
自己拍的照片。若场景里存在"同网络有不受信任的人"，这套改动就需要重新评估。

## 六、验证工具与实测结论

上面"安全影响"那一节是分析结论；`tools/sonyconnect_sniff.py` 把它变成**可复现证据**：
解析 SonyConnect 自己的协议（PTP/IP 帧 + 厂商操作码），重点标出配对码、文件名、
照片内容三类明文。

两条自检路径（都不需要真相机）：

```bash
python tools/sonyconnect_sniff.py --selftest   # 合成帧流按 7 字节切分喂进解析器
python .workbuddy/smoke_sniff.py               # scapy 真发 IP/TCP/UDP 包，抓回来解析
```

实测结果（2026-09-12，回环口真包）：

- 控制面：Init 握手 → `PAIR_BEGIN`（手机设备名）→ `PAIR_EXCHANGE` →
  **配对码明文可见并高亮**；
- 文件面：`DATA_OPEN` 里的一次性令牌明文可见；`Start/Data/End` 拼回来的字节流被识别为
  **JPEG（明文照片流）** 并落盘，头部 `ff d8 ff e0 … JFIF` 完好 —— 照片在链路上
  没有任何保护，这是最直接的证据；
- 发现面：UDP 探测应答里的协议端口 / 文件端口 / 配对模式 / 已有配对 全部可读。

**一个必须说清的限定**：被动嗅探只有在你位于链路路径上时才看得到内容。相机与手机之间的
Wi-Fi 是 WPA2、每客户端一把密钥，所以在同网段"旁听"通常什么都抓不到。要复现上面这些
输出，得选一种抓包位置：① **你是 AP**（相机用 Wi-Fi 客户端模式加入你开的热点，Windows
移动热点即可）—— 不需要任何攻击；② 交换机镜像口 / 能解 WPA2 的监听模式；③ 同网段
`--arp-spoof` 把自己插进路径（主动干扰，需 IP 转发，只在自己网络上用）。

也就是说，"同网段就能看到"这个说法要加一个前提 —— **得先把自己放进路径**。一旦放进去
（当 AP 或 ARP 欺骗），内容就完全明文：配对码与照片都一览无余。
