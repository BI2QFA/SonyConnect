# 2026-09-13 提速：数据帧零分配、单拷贝

配套的手机端改动见手机工程 `devlog/2026-09-13-传输发现连接三处提速.md`。

## 问题（传输热路径）

`PtpIpServer.transfer()` 每 128 KiB 走一次 `PtpCodec.dataPacket(src, off, len)`：

```
dataPacket:  byte[] p = new byte[4 + len];        // ① 128 KiB 载荷副本
             System.arraycopy(...)
             frame(): byte[] out = new byte[8 + p.len];   // ② 又一个 128 KiB 整帧
             System.arraycopy(...)
```

**每块两次分配、每个字节拷两遍。** 25 MB 的文件 = 200 块 → 约 **50 MB 垃圾 + 50 MB memcpy**
（按"每次分配 128 KiB×2、每字节两遍"计），而相机只有很小的堆、CPU 也弱 —— GC 抖动直接压住吞吐。

## 改法：就地写帧

新增（`PtpCodec`）：

- `DATA_PAYLOAD_OFFSET = HEADER_LEN + 4` —— 数据帧里载荷的起始下标（包头 8 + 事务号 4）
- `dataFrameCapacity()` / `dataFrameLen(payloadLen)`
- `fillDataFrame(frame, type, txId, payloadLen)` —— **只写 12 字节包头**

`PtpIpServer`：

- `Conn.send(byte[] framed, int off, int len)` —— 写复用缓冲里的那一段（顺手去掉 `flush()`：
  `out` 是裸 socket 流，本来就没有缓冲层，那句是空操作）
- `transfer()`：**一次传输只分配一块** `dataFrameCapacity()` 的缓冲，数据由
  `readInto(..., frame, DATA_PAYLOAD_OFFSET, want)` **直接读进载荷区**，然后 `fillDataFrame()`
  写包头、`send(frame, 0, dataFrameLen(got))` 发出去 —— 全程**零额外分配、零额外拷贝**。

## 验证

相机端桌面回归**全绿**（TestMain 21 / ProtocolTest 168 / PairingStore 57 / AppLog 12 /
Batch 361）。ProtocolTest 里有**逐字节比对**的数据口取文件、分片续传（offset+length）与
token 一次性等断言 —— 也就是说这条改动是**字节级验证过**的，不是"编过就算"。

⚠ 装新包前**先卸载旧版**（相机端铁律；versionCode 未动，仍是 2.0/vc1）。
装机包：`app\app\build\outputs\apk\debug\app-debug.apk`。
