# SonyConnect 相机端 — STATUS

**版本**：2.0（versionCode 1）　**包名**：com.bi2qfa.sonyconnect（与手机端一致）
> versionCode 由用户定为 **1**（2.0 版本线的第一个包）。装上它**必须先卸载旧版** ——
> 相机上装过到 vc28，安卓拒收降级覆盖安装；卸载会清掉配对表，装完要重新配一次手机。

**协议**：PTP/IP（自研，非索尼原厂）—— 协议端口从 15740 起候选，文件端口 = 协议端口 + 1。
旧 FTP 2121 / 私有 2122 的代码仍在树里，**仅作真机验收期的回退**，验收通过后删除。

**加密**：**已整体移除**（2026-09-12，用户决策）—— 控制面与文件面全程明文，
准入判定唯一依据是配对表。详见 `devlog/2026-09-12-去加密.md`（含安全影响与回退路径）。

## 已知边界

- 旧 FTP/私有协议代码与 PTP/IP 共存（端口不同，可同时运行），验收通过后删除。
- EXIF 兜底给不出序列号（本机不写 0xA431）；SD 卡无照片且原生读失败时型号显示 "—"。
- Wi-Fi 模式下相机 IP 由 DHCP 分配，变化后已建立的连接会断（手机端心跳感知并重扫）。
- 强制配对的代价（有意为之）：新相机端**只认配对过的手机**，通讯中断只能靠相机
  物理菜单恢复，没有远程后门。
- 两端记录不同步时的自愈（2026-09-12 修复）：相机侧有本机记录、手机侧丢了时，手机端
  配对会被相机以 `0x2005` 回绝（已授权会话不受理 `PAIR_*`），此时手机端**不再验码**，
  直接把本地记录补齐并连上 —— 准入那道门没变，变的只是手机端对齐事实。因此
  "用错码测拒绝"必须在**两端都无记录**的前提下测。
- **链路明文**（用户定版决策）：照片与文件名在同网段可被抓包看到，配对码也明文过网，
  且没有重放防护。准入仍然强制（未配对一律拒），但配对过不再等于链路私密。
  加密版完整保存在 git 上一提交，需要时可回退。

15. **"停线程/关 socket" ≠ "句柄已释放"**：`interrupt()` 只是打断阻塞、`socket.close()`
    只是让下一次收发抛异常 —— 线程若正卡在 SD 卡的一次文件读里（缩略图 / 照片 / 目录），
    它手里的 `RandomAccessFile` 要等**这一轮读完**才在 `finally` 关。退出链最后一句
    `DAConnectionManager.finish()` 一执行进程就没了，正好卡进这个窗口就留下一个没归位的
    占用 —— 相机把它当成图像数据库失同步，下次开机挂"正在修复数据"。
    凡"退出前必须释放的资源"，停的时候都要 **join 一把（带上限）**，不能只发信号。
16. **别在回调里写死"落地屏"**：`beginModeSwitch()` 的完成回调原先硬写
