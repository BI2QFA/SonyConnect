# 多设备适配 + 配对解除同步 + MD3E 悬浮导航

一轮较大的改动，横跨协议、数据层与双端 UI。下面按"为什么这么改"组织，纯实现细节
看代码注释（关键处都写了"为什么"，尤其是几个容易改回去的地方）。

---

## 一、多设备适配（手机端数据层）

### 1.1 下载队列按设备隔离（不再"换设备就清空"）

旧行为：`TransferStore.onCameraChanged()` 发现连的相机换了就把**整个队列清掉**。
当时的理由是"条目主键是相机内路径，两台相机上完全一样，混用会让续传从别人的
`.part` 断点开始写"——理由成立，但处理方式过头了：用户切一圈设备回来，待传任务
和断点全没了。

现在改成**按设备分桶**：

- 持久化结构 `queues` = `{设备码: [条目…]}`，当前桶由 `cameraGuid` 指明；
- 切设备 = 先把上一台的任务存回它自己的桶，再装载新设备那一桶；
- 1.0 的旧全局队列（`items` 键）**只读不删**地当"当前桶"迁移，升级不丢队列；
- "不跨设备混用"这条纪律原样保留 —— 正是分桶要保证的事。

### 1.2 下载落到 `设备型号_SN码` 子目录

`StorageSink.deviceFolderFor(guidHex)` → `sanitizeDirName(型号 + "_" + SN)`，
例：`ILCE-6300_05186914`。型号/SN 取自配对记录（手机端唯一同时存这两项的地方）；
两者都不全时**退化为设备码**，绝不退化成公共目录 —— 退到公共目录等于把两台的文件
静默混回去。名字里的 `/ \ : * ? " < > |` 与控制字符一律换成 `_`（一个带 `/` 的
名字会直接变成两级目录，甚至把 SAF 建档打偏）。

两条纪律：

- **子目录名跟着条目走**：`TransferItem.deviceDir` 入队时钉进去并持久化。现算
  （读当前连接设备）会在切换设备后指向错目录，续传更会写到另一台的 `.part` 上。
- **落盘与打开文件走同一个函数**：`StorageSink.localRelPath(deviceDir, cameraPath)`。
  两边各算一次迟早不一致，表现是"传输页显示已完成、点开却说文件不存在"。

### 1.3 实时信息在连上后立刻拉一次

电量/镜头只跟着 3 秒心跳走，所以建立连接后不主动补一发，主界面会先空几秒——
用户看到的就是"进主界面要等几秒才刷出来"。现在连接与配对两条路径都在落占位信息后
立刻 `OP_PING` 一次（`ConnectionCenter.applyLivePing`）。

## 二、连接状态可见 + 配对解除双向同步

### 2.1 相机端主屏显示"手机端：已连接/未连接"

依据是相机端**当前有没有已授权的控制会话**（`PtpIpServer.connectedClientCount/Name`），
不是"配对表里有几台"——配对是历史，连接是当下，配对表非空但没人在线是常态。

主屏新增 1 秒轮询 `mainTicker`（连接/断开是外部 TCP 事件，相机端没有回调可挂，只能轮询），
且**文本没变就不碰视图** —— 否则每秒重渲一次二维码位图。

### 2.2 已连接时解除配对 → 协议通知对方

| 方向 | 通道 | 行为 |
|---|---|---|
| 手机解除 | `OP_PAIR_REMOVE`（已认证会话内，原本就有） | 相机删记录 |
| 相机解除 | **新增** `EV_PAIRED_REMOVED`（事件连接推送） | 手机清本地记录 + 断开当前会话 |

相机端在配对页删某台手机时，若那台正连着就推事件（`pushPairRemoved`）。手机端在
事件回调里清记录并 `disconnect("相机已解除与本机的配对")` —— 提示直接上屏。

### 2.3 未连接时单方解除（通知送不到的那一半）

- **手机解除、相机没有**：不做任何处理（用户定版）。手机端未连接时不会去通知相机，
  相机那条记录就留着；下次配对时相机回 `RC_NOT_SUPPORTED`，手机端按"相机认识本机"
  自愈补齐（见去加密那轮的修复）。
- **相机解除、手机没有**：手机端下次连接会被 `Init Fail(NOT_PAIRED)` 挡回来 —— 这就是
  送不到的"未配对通知"。手机端现在据此**自动清掉本地记录**并把提示换成
  "相机已解除与本机的配对，请重新配对"。

  这里必须动本地数据：不清的话 UI 因为"本地认为已配对"而永远只给"连接"按钮，
  用户怎么点都连不上。清掉后界面自然回到"配对"入口。

为了让手机端能分辨拒绝原因，`ObjectRepository.connect` 的返回值从 `Boolean` 换成
`ConnectOutcome{OK, NOT_PAIRED, BUSY, FAILED}`（`initFailReason` 本来就在线上传着，
只是过去被 `catch(Exception)` 吞掉了）。

## 三、设备被占用（相机端）

1. **另一台正在配对中**：`serveControl` 在发 Init Cmd Ack 之前就查
   `isPairingInProgress()`，命中直接回 `Init Fail(BUSY)`。不能只把连接晾着 ——
   那样手机端只能等到请求超时，报出来的是"网络不好"，用户会反复重试。
   `pairingLoop` 里还留了一个竞态兜底：抢不到独占权时收下它的 `PAIR_BEGIN` 并回
   `RC_DEVICE_BUSY`（此刻 Ack 已发出，再补 Init Fail 会被手机端当成操作应答解析）。
2. **相机已被连接**：`evictOrReject` 原本就拒（不同 deviceId 有活跃控制会话 → BUSY），
   现在有断言钉住。

手机端把这两种情况分别上屏："相机正被其他设备占用（配对中或已连接），请稍后重试"，
不再和"配对码不正确"混为一谈（后者会让用户反复重输那个码）。

## 四、手机端交互

### 4.1 连接页 → 配对页（模式互斥）

`DisconnectedScreen(forcePair)` 现在是配对/连接二合一：

- 默认模式：**本机一台都没配过 → 配对模式**（此时唯一有意义的事就是配对）；
  配过 → 连接模式。页内可切换，设置页"配对新相机"手动进配对模式。
- 两个模式扫到的设备**互斥**，靠探测应答里的 `pairingMode`（配对窗口开着才是真），
  不是靠过滤名字：连接模式只列没开窗口的，配对模式只列开着窗口的。
- 配对模式下列表里点一下就是弹 6 位码框；连接模式下列已配对的直连、未配对的引导去配对。

### 4.2 MD3E 悬浮导航（看图一实现）

- **药丸**：**手摆**（`NavPill` + `NavPillItem`：64×48 触摸位、26dp 图标、宽度随内容），
  三个图标、**无文字**。

  ★★ **不要改回 `ShortNavigationBar`** —— 第一版就是用它，结果 adb 截图一看
  **圆形按钮整个不见了**：它是**占满宽度**的栏（设计上就是整条底栏），放进 Row 里
  把整行吃光，右边的按钮被直接挤出屏幕。图里要的是"药丸 + 圆形按钮"两个**独立**
  控件，所以药丸必须自己摆、宽度只占自己那一份。
- **圆形按钮**：原来的圆角矩形"错号"改成 `FilledIconButton(shape = CircleShape)`
  （**带阴影**，与药丸一致），内缘嵌一圈 `CircularProgressIndicator` —— 它就是原来的
  顶栏进度指示窗（圆环承担进度，点击展开）。顶栏那个进度图标已删除。
  进度环的取值有两条纪律（都是实测踩出来的）：
  ① **不把"已暂停"当成"有进度"** —— 点开始传输的瞬间缩略图管线先被暂停、
  `batchRunning` 还没置位，那时 `batchDone == batchTotal`（10/10）会被算成 100%，
  于是满圈闪一下再掉回真实进度；
  ② 下载进行中优先表下载字节进度，否则才表缩略图张数。
- **选中指示 = 与药丸同形的小药丸**（用户定版），并且与按压水波纹**同形同大**：
  水波纹不指定 radius（`ripple(radius=…)` 只能画圆，做不出药丸），而是铺满条目自身、
  由 `clip` 裁成同样的圆角 —— 两者天生一致，不必再对尺寸。底色必须画在 `clickable`
  **之前**，否则会被水波纹盖住（Compose 链上靠前的先画）。
- **真悬浮（不遮挡内容）**：悬浮栏**不占** Scaffold 的 `bottomBar` 槽位 —— 那个槽位
  就是"预留 + 内容躲开"的旧式遮挡处理（用户反馈"下面字被切割，说明还留着遮挡"）。
  改成 `Box` 覆盖在内容之上，内容铺满整屏；主页/文件/传输三个可滚动页底部留
  `FloatingNavInset`，最后一项照样能滚到栏上方；文件页与传输页的 FAB 也一并抬高
  （实测被圆形按钮压住，只露出"始…(1)"）。
- **悬浮窗三段**：① 下载进度 + 缩略图（`batchRunning || batchTotal > 0` 时才显示）
  ② 设置 ③ 已绑定设备（点一行切换，当前那台标"已连接"）。
- 点设备行切换走 `ConnectionCenter.switchTo`：先收掉当前会话（相机端同时只服务一台）→
  扫一轮**按设备码认人** → 连接。认人不认地址：Wi-Fi 模式下地址由 DHCP 分配会变，
  设备码不变 —— 这也是"按设备切换"能成立的前提。
- 顶栏副标题挂相机型号/SN，多设备下"现在连的是哪台"一眼可见。

### 4.3 MD3E 实测结论（重要，别再走回头路）

material3 1.4.0（compose-bom 2026.08.00）里：

- **有且稳定、无需 opt-in**：`ShortNavigationBar` / `ShortNavigationBarItem`、
  `FlexibleBottomAppBar`、`WideNavigationRail`、`AppBarRow/AppBarColumn`。
- **只有设计令牌、没有实现**：`FloatingToolbar`、`DockedToolbar`、`LoadingIndicator`、
  `ButtonGroup`、`SplitButton`、`MaterialShapes` —— 想要只能自己摆。
- `ExperimentalMaterial3ExpressiveApi` 存在但是**死注解**（只有它自己引用自己），
  写 `@OptIn` 是多余的。
- **两个坑**：① `MediumFlexibleTopAppBar` / `LargeFlexibleTopAppBar` 在 JVM 层是 public，
  但**没有 Kotlin 元数据**，Kotlin 侧写不出来（Unresolved reference）—— 顶栏因此仍是
  普通 `TopAppBar`（它已废弃但能用）。② `MaterialTheme.motionScheme` 是 **internal**，
  expressive 动效规格只能照数值自己写弹簧（见 `FloatingNav.kt` 末尾）。

## 五、相机端交互

- **弹窗优先级**：没有网络模式时先弹"尚未选择网络连接方式"（确认后进模式页）；
  服务跑起来后若一台都没配过，再弹"尚未配对任何手机"（确认后进配对页）。
  顺序是有理由的：没有网络模式就没有服务，配对页也没意义。
- **配对成功自动回主页面**：`PtpCameraHandler` 新增可选回调 `PairingEvents`
  （与既有 `ExitCallback` 同一套路，内核保持零 Android 依赖），相机端在
  `onPaired` 里 post 回主线程 → 离开配对页 → 主屏；主屏那行
  "手机端：已连接（名字）"就是成功的证据。
- **输错 5 次**：`onPairingFailed` 把"第几次失败 / 是否用满"报给 UI（`used` 必须在
  `noteFailure` 之前算——用满时 `closeWindow()` 会把计数清零）。用满即弹窗告知，
  返回配对页时 `enterPairingMode()` 会重开窗口、**自动换新码**。
- **通知弹窗零新增布局**：复用确认弹窗的面板（同一套几何/字体/焦点纪律），只把
  "取消"藏掉、"确定"改文案。借用的代价是收尾必须恢复面板形态，统一放在
  `runConfirmAction` 里做；左/右键在通知态不动焦点（否则会移到已隐藏的按钮上）。

## 七、待真机复验（这轮改动最需要盯的几处）

1. **多设备**：配第二台相机 → 两台都出现在悬浮窗"已绑定设备"里 → 点另一台能切过去；
   切回来时各自的队列还在。
2. **下载落盘**：勾文件下载 → 用户选的下载目录里应出现 `型号_SN/DCIM/…` 子目录；
   传输页点开已完成文件能正常打开（落盘与打开走同一路径函数）。
3. **配对解除同步**：连着的时候在**相机**上解除配对 → 手机应立刻提示并断开、
   设置页里那台也消失；反过来在手机上解除 → 相机配对页列表同步消失。
4. **送不到的那一半**：相机关机时在相机上解除配对 → 手机再连 → 应提示
   "相机已解除与本机的配对"并回到配对入口（本地记录已自动清）。
5. **占用**：手机上正在配对时用第二台手机连/配 → 应明确提示"被其他设备占用"。
6. **相机端**：无网络模式时弹模式窗、无配对时弹配对窗（前者优先）；配对成功自动回
   主屏；刻意输错 5 次 → 弹窗 + 新码；主屏"手机端：已连接/未连接"随手机连断实时变。
7. **导航观感**：药丸/圆环/悬浮窗三段的位置与手感（这轮全是按 MD3E 规格手摆的，
   没有真机目视过）。

## 八、导航观感：这轮终于"改完自己看得见"

前一轮的导航是纯按规格手摆、没目视过，结果丢了整个圆形按钮。这轮改用**截图自查**
闭环：`adb exec-out screencap` 抓屏 → 自己看图 → 再改。用这个办法确认了
药丸比例、圆球阴影、小药丸指示、按压水波纹同形、列表末项完整露出，
并发现了两处只有看图才知道的问题（按钮被挤出屏幕、FAB 被圆形按钮压住）。

关键教训：**视觉改动必须截图核对**，靠"按规格推断"会漏掉布局层面的失败
（占满宽度的组件把邻居挤出去这类问题，代码读起来完全正常）。
