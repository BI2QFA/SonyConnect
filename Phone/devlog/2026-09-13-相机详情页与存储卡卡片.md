# 2026-09-13 相机详情页 + 存储卡卡片（手机端）

承接 `2026-09-13-MD3E换装.md`。这一轮是**功能**不是换皮：相机新增四组固定信息，
主页按用户定版重排，并多了一个二级页。

## 一、用户要什么

原话（2026-09-13）：

> 相机端读取 backup region / android version(包括 sdk 版本) / java api 版本 /
> 相机内 sd 卡总容量和已用空间，这些作为和固件版本之类的一样的固定信息传输，
> 不用实时更新。现在需要让主页的相机信息卡片可以点击，点击进去展示相机详细信息如
> "型号 序列号 地区 固件版本 安卓版本 java版本"。在主页外露的卡片中仅保留电量，
> 现在的电量是单独的卡片，应显示在相机卡片中，sd 卡总容量和已用空间单独一个卡片
> 显示在主界面。

拆成四条：

1. 相机端能读到地区 / 安卓版本+SDK / Java API 版本 / SD 总量与已用；
2. 这些走 `OP_DEVICE_INFO`（**固定信息**），不进 3 秒心跳；
3. 主页相机卡可点 → 二级页展示那 6 项；
4. 主页相机卡只留电量（电量从独立卡片并进来），SD 另起一张卡。

相机端那一半的"怎么读到"写在相机端 devlog
`SonyConnect/devlog/2026-09-13-相机固定信息与SD容量上报.md`，这里只说手机侧。

## 二、数据契约（两端逐字对齐）

相机端 `PtpCameraHandler.deviceInfo()` 在原有 6 个键之外新增 6 个：

```json
{"name":"...","model":"ILCE-6300","serial":"05186914","firmware":"3.10",
 "region":"CHINA","apiVersion":"2.3","androidVersion":"4.1.2","androidSdk":16,
 "sdTotal":31914983424,"sdUsed":12884901888,"mode":"hotspot","ssid":"..."}
```

约定（沿用既有纪律）：

| 类型 | 未知表示 | 手机侧读法 |
|---|---|---|
| 字符串（region / apiVersion / androidVersion） | 空串 | `optString(key, "")` |
| 数值（androidSdk / sdTotal / sdUsed） | `-1` | `optInt` / `optLong`，缺省也取 `-1` |

★ **数值键必须是数值型**（相机端 `SJson.member` 的 long 重载，不加引号）——
手机端用 `optLong` 读，写成字符串会**静默**回落成 -1，界面永远显示 "—"。
相机端桌面回归里专门加了一条断言盯住这点（`!contains(blob, "\"sdTotal\":\"")`）。

## 三、手机端改了什么

### `data/CameraInfo.kt`
6 个新字段 + 解析；新增 `UNKNOWN_SIZE = -1L` 哨兵与两个派生量：

```kotlin
val sdKnown: Boolean get() = sdTotalBytes > 0 && sdUsedBytes in 0..sdTotalBytes
val sdUsedFraction: Float get() = if (sdKnown) (sdUsedBytes / sdTotalBytes).coerceIn(0f,1f) else 0f
```

★ 判定统一走 `sdKnown`，**不直接比 0**：只拿到总量或只拿到已用都算不出来，
那就该显示 "—" 而不是画一条假进度条。

### `data/DeviceStore.kt` —— 顺手修掉一个真问题

`apply()` 原本只保电量/镜头/镜头名三个"快照里没有的实时字段"。新增的固定信息
没被保，而连接流程是**先落 placeholder、再拉全量**，placeholder 这几项按定义就是空的：

- 每次重连都会让详情页和存储卡闪一下 "—"；
- 更糟的是**全量拉取失败时**（相机忙 / 这一次超时），已经读到过的地区会**永久丢掉**
  —— 而地区 / 安卓版本 / Java API 版本在手机侧**没有任何本地兜底**
  （型号与 SN 还能从配对表补）。

同一个 guid 下这些值不可能变，所以按"空/未知则保留旧值"合并，与电量同一条规矩。

### `ui/screens/HomeScreen.kt`
- **相机卡整卡可点**（`GroupCard(onClick=…)` + 行尾 `Chevron()`）→ 进相机详情；
- 机型 `maxLines=1` + 省略号：长机型名换行会把行尾那个 "›" 顶到下一行，
  而那是"这张卡能点"的唯一提示，宁可截机型也不能把它挤走；
- **电量并进相机卡**，原独立的"电量"区块整块删除；
- 新增"存储卡"区块：`已用/总容量` 大号读数 + 弹簧进度条 + `已用 X% · 剩余 Y`。

★ 两张读数卡都加了**静态标签**（"电量" / "已用 / 总容量"）。这不是装饰：
电量原来靠"电量"这个区块标题交代语境，并进相机卡后标题没了，只剩一个大号 "—"
挂在机型下面 —— 24sp 的破折号有 40px 宽，**看着就是一条横线**（截图里像坏掉的进度条）。
装机截图对照过才发现的。

### `ui/screens/CameraDetailScreen.kt`（新）
6 项分两组（设备：型号/序列号/地区/固件版本；系统：安卓版本/Java API 版本），
**字段名在左、值在右**（`title` + `trailing`），就是 Android"关于手机"和索尼相机
自身菜单那一套。安卓版本按用户要求带上 SDK：`4.1.2（SDK 16）`（两个来源缺一个
就不写半个括弧）。

★ 这一页**刻意不用 `IconCircle`**：那是"点进去还有东西"的菜单入口记号，
而这里每行都没有下一层，配上箭头/圆片反而会让人以为还能点。

### `ui/MainActivity.kt`
- 新 state `showCameraDetail`；`screenKey` 加 `"cameraDetail"`；
- BackHandler 链里给它一条（登记在最前 = 优先级最低，与它的层级一致）；
- 悬浮导航的条件加 `!showCameraDetail`（二级页让位，与设置页一致）；
- 顶栏 `pageTitle/onBack` 加一条：`"相机信息" to { showCameraDetail = false }`。

★ **转场**：`settingsOrdinalOf` 换成 `navPosOf`，返回 **（导航树, 树内层级）**：

```kotlin
key == "tab0" -> "camera" to 0
key == "cameraDetail" -> "camera" to 1
key.startsWith("settings:") -> "settings" to (…ordinal…)
else -> null
```

只有**同树且层级不同**才播共享轴推进/推回。为什么非要连树名一起返回：
单看数字 `tab0`(0) → `settings:1`(1) 深度也在变大，只比数字的话主页进设置也会被
判成"往里推"，而那条转场是**用户定版过的纯淡入淡出**，不能动。
现在主界面↔相机详情同样是一对"上一层/下一层"，进用 `spatialDefault`（从容推开）、
出用 `spatialFast`（干脆让位），返回自动反着播。

### 其它
- `ui/ProgressUi.kt` 新增 `formatCapacity`：**补上 GB/TB 段**。工程里原有的两份私有
  `formatSize` 只到 MB（格式化的是单个文件，量级封顶几十 MB），存储卡是 GB 级量，
  没 GB 分支的话 32GB 会印成 "30518 MB"。进制用 1024，与工程既有三份一致 ——
  同一块卡在相机菜单里和这里数字要对得上。
- `res/drawable/ic_sdcard.xml`（新）：工程里原本**没有**存储卡/容量类图标。

## 五、安全 / 稳定性影响

- **不新增权限、不新增进程、不改协议帧**：只是 `OP_DEVICE_INFO` 的厂商 JSON 多了
  6 个成员，长度增加约 110 字节，仍远在单包以内。
- **相机端读取全部包在 `try/catch Throwable` 里**，任一属性取不到就是空串/-1，
  不影响连接、不影响其它字段。地区用 `ScalarProperties.getInt` 失败后还会退一步
  试 `getString`。
- **SD 容量做了合理性拦截**（`total<=0` 或 `>4TiB` 一律判读不到）：相机上
  `getRootDir()` 有时会落到一个"存在但不是挂载点"的空目录，这时 statfs 报的是
  父文件系统的大小 —— 看着像真值其实是错的，宁可返回 -1 让界面显示 "—"。
- 心跳包（`OP_PING`）**没有变大**：这 6 项不进实时通道，用户明确说不用实时更新。
  SD 容量口径上会变（换卡、边拍边填），但与其余固定信息同为"一会话一快照"，
  重连即刷新，不为它单开一条通道。
