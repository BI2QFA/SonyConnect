# 2026-09-18 手机端：图标换 Material Symbols 可变字体 + 动态取色 + 预览手势

用户这一轮对手机端提了三条：

> 手机端界面修改 更换 material symbol 图标
> 还有把那些花花绿绿的图标的背景换成动态取色
> 大预览图支持左右滑动放大选中

另加一条两端都要的：

> 每个图标都要利用 symbol 图标的可变功能做出点击时 q 弹的感觉 按下缩小 松手回弹

---

## 一、图标换成 Material Symbols 可变字体（本轮最大的一处）

### 为什么不是"下载 SVG 转成 vector XML"

我第一版就是那么做的（官方 SVG → `res/drawable/ic_*.xml`，30 个文件）。**能跑，但用不到可变轴** ——
用户明确要求"每个图标都要利用 symbol 图标的可变功能"，而**可变轴只存在于字体文件里**，
从 SVG 转出来的 path 是死的。所以整个方案换成字体。

### 素材与子集化

- 官方可变字体：`google/material-design-icons` 的
  `variablefont/MaterialSymbolsOutlined[FILL,GRAD,opsz,wght].ttf`（**10,678,048 字节**）。
  ★ 不能用 Google Fonts 的 `css2` 接口拿 —— 那个接口按字重返回**静态实例**
  （我验证过：下的那份只有 15 张表、**没有 `fvar`**，FILL/wght 一动都不动）。
- 子集化到只含这 30 个图标 → `app/src/main/res/font/ms_icons.ttf`，**34.5 KB**。
- 脚本 `tools/subset_ms_font.py`（幂等，可复跑）。
- 子集后**四轴全在**（`fvar`/`gvar`/`avar` 都在），且**渲染级验证过插值仍然工作**
  （同图标在 FILL=0/1 与 wght=100/700 下墨迹像素确实不同）。

### 关键 API 事实（这一条踩了很久，记下来）

**这个依赖版本（ui-text 1.13.0-alpha03）里 `TextStyle` 没有 `fontVariationSettings` 参数。**
javap 核过：`TextStyle.class` 里 `grep -ci variation` = **0**。所以网上常见的
`TextStyle(fontVariationSettings = ...)` 写法**编译不过**。

正规入口是 **`Font`** 的属性：

```kotlin
Font(resId, variationSettings = FontVariation.Settings(
    FontVariation.weight(w), FontVariation.Setting("FILL", f), FontVariation.Setting("opsz", 24f)))
```

也就是说：**轴值一变就得换一个 `Font` 对象**。这是本轮实现形态的根据（见下面的量化）。

另外注意：`androidx.compose.foundation.gestures.detectTapGestures` 在这个工程里
**编译类路径上找不到**（foundation 是经 material3 传递进来的，不是直接依赖）。
`MsIcon` 里因此改用 `clickable(interactionSource=…, onClick={})` 取"按下"信号，
代价是一点水波纹。**不要因为一个图标组件去改构建配置。**

### Q 弹反馈：两层，缺一不可

| 层 | 内容 | 覆盖范围 |
|---|---|---|
| 主 | 缩放 1.0 → **0.82**，松手用 `DampingRatioMediumBouncy` **spring 回弹**（有一点过冲才是"Q 弹"） | **所有**图标 |
| 辅 | `FILL` 0→1（空心→实心）+ `wght` 400→500 | FILL 只在支持的图标上生效 |

★ **FILL 轴只在 30 个图标里的 14 个上有效** —— 这是实测结论，不是猜测：
Material Symbols 里有一半图标天生只有一个形态，FILL 从 0 到 1 是**同一个字形**。
官方原版字体同样如此（我用 10.2 MB 原版复核过 refresh / add / check / menu / arrow_back 等）。
- **有效（14）**：delete, draft, folder, grid_view, home, image, info, palette,
  photo_camera, photo_camera_back, play_arrow, settings, stop, water_drop
- **无效（14）**：add, arrow_back, check, chevron_right, contrast, deselect, download,
  list, redeem, refresh, select_all, swap_vert, tune, wifi

所以 **Q 弹的主效果必须是缩放 + spring**（对所有图标成立），FILL 是加分项。
`MsIcon.supportsFill` 把这份名单写进代码、`tools/check_icon_axes.py` 负责核对
（换图标或升级上游字体后必须重跑）—— 否则下一个人看到"一半图标按下去没反应"会当成 bug 去乱改。

### 轴值必须量化（否则动画期间每帧重建 Typeface）

轴值不同的 `Font` 在 Compose 的 `AsyncTypefaceCache` 里是**不同条目**，而那个缓存是 **LRU 16**。
不量化的话，一次 spring（300~500ms × 60/120Hz）会产生 18~60 个中间值，
**每帧都超出缓存 → 每帧重建一次 Typeface**。

量化取值（由 `MsIcon.kt` 的 `FILL_STEPS` / `WEIGHT_STEPS` 控制）：

- **FILL 8 档**（步长 1/8）：单次动画组合数 ≤ 9，稳在 LRU 16 以内。
- **wght 步长 10**（400/410/…/500）：依据是 `gvar` 在 wght 上**稀疏采样** ——
  实测墨迹 400→450 几乎不动（1102→1110），450→460 一次跳 140，之后缓动。
  步长 10 正好把那个跳变限制在 1 档内。

手感取舍的依据：FILL 的按下动画只有约 150~200ms，人眼在这个时长能分辨的离散台阶上限大致
12~16 级；8 档时单档变化约占图标墨迹 26%（偏跳），但**缩放同时在动**，形变边缘一直在移动，
台阶会被盖掉一部分。若真机上看得出"一格一格"，把 `FILL_STEPS` 调到 12（代价：偶发淘汰）。

### 调用点迁移

47 处 `R.drawable.ic_*` 全部换掉（编译器驱动：它精确报出每个类型不匹配的位置）。
为保住"装饰图标不抢整行点击"这条，做了两个基础设施：

- `IconCircle` / `RowIconAction` / `Chevron` 等**参数类型从 `Int` 改成 `MsIcon`**；
- `SettingsRow` 建一个 `InteractionSource`，用 **`LocalRowInteraction`**（CompositionLocal）
  递给行首圆片里的图标 —— 这样"整行被按住 → 图标跟着 Q 弹"，
  而图标**不需要**自己装手势（自己装就会把整行点击抢掉，很难查）。

★ 有几处**必须显式 `animated = false`**（不让图标参与按下反馈）：`Chevron`（纯指示图形）、
开关滑块里的对号、网格/列表的占位图标（一次几十个）、选中角标 —— 它们都在
"外层已经可点"或"数量多"的位置。

### ★ 一个真 bug：图标不能自己装 `clickable`（已修）

第一版的 `MsIcon` 在"调用方没给 `interactionSource`"时会**自己装一个空的
`Modifier.clickable`** 来取按下信号。**这是错的，而且症状很隐蔽**：

本工程里绝大多数图标都嵌在**可点的父容器**里（`FilledIconButton` / `ListItem` /
`ExtendedFloatingActionButton` / `Surface(onClick)` / `ExpressiveButton` …）。
Compose 的嵌套点击**内层优先** —— 图标那个空 `onClick` 会把父容器的点击吃掉。
症状是"**手指正好按在图标上时按钮没反应，按旁边就行**"，一小块死区，
装机也不一定立刻发现（谁会让手指精确落在图标中心）。

修法：改用 `pointerInput` + `awaitPointerEventScope` **只观察、不消费**：

```kotlin
Modifier.pointerInput(Unit) {
    awaitPointerEventScope {
        while (true) {
            val e = awaitPointerEvent(PointerEventPass.Initial)   // Initial 阶段只读
            selfPressed.value = e.changes.any { it.pressed }
        }
    }
}
```

- 全程**没有** `consume()`：事件继续往上传，父容器照常收到点击；
- 这样两种场景（图标嵌在可点容器里 / 图标自己就是可点目标）**用同一套代码都对**，
  调用方不需要知道区别；
- 顺带没了水波纹（原来那个 `clickable` 会带一点，本就不该有 —— 图标不是按钮）。

★ 不用 `detectTapGestures` 的原因：它属 foundation 的**非传递 API**（本工程的
foundation 是经 material3 进来的），编译类路径上找不到；而
`awaitPointerEventScope` / `PointerEventPass` 在 `ui` 包里，直接可用。

当时是子代理在静态分析里**怀疑**到这个风险（列出 6 处嵌套调用点），
我核实后确认成立并修掉 —— 这类"内层吃掉外层点击"的问题**光看编译是发现不了的**。

### 收尾

- 删掉 29 个不再引用的矢量 XML（`res/drawable/ic_*.xml` 从 30 个剩 1 个）。
- **`ic_stat_transfer` 必须保留**：通知栏 `setSmallIcon` 只能用资源 drawable，字体字形在那里用不了。
- `tools/render_icons.py` 改成**渲染字体**（码位从 `MsIcon.kt` 读，不另抄一份表），
  仍保留矢量 XML 那条路给 `ic_stat_transfer`。

## 二、图标底色改动态取色

用户原话："把那些花花绿绿的图标的背景换成动态取色。"

原来 `IconTints` 是**写死的 Google 容器色**（`#D3E3FD` 之类），而且注释里明确写着
"故意不跟随主题色相"（理由是"跟着主题走会变成同一个颜色的六个深浅"）。

改法：**用不同色角色解决"六个深浅"的顾虑**，而不是靠固定色：
`primary` / `secondary` / `tertiary` 在动态取色下本来就是**三个不同色相**，
再加 `*Fixed` 档补两个更亮的变体，凑齐六枚互不相同的圆片。

实现上把 `val` 改成 **`@Composable get()`** —— 十九个调用点**一个字都不用改**，
而取值时机从"类加载"挪到"组合时"，于是会跟着主题（壁纸）重组。

★ 顺带修了一处语义错误：原来"粉色"这一档在设置页里给"外观""调色盘"这类**装饰行**用，
改动态取色时若直接映射到 `errorContainer`，那几行会变成**红底** —— 红色在 MD3 里是
"出事了"的信号。所以拆成两个：`Pink`（secondaryFixed，装饰用）与
`Error`（errorContainer，只给"传输失败"这类真正的失败态）。

## 三、大预览图：左右滑动 + 缩放拖动 + 选中

原来只有一个 `Image(fillMaxSize)` + "单击任意处退出"，**零手势**。

四个手势的分工（这一屏最要紧的事）：

| 手势 | 未放大（1x） | 已放大（>1x） |
|---|---|---|
| 单指拖动 | 切上一张/下一张（Pager） | 平移图片 |
| 双指捏合 | 缩放 | 缩放 |
| 双击 | 放大到 2.5x | 复位到 1x |
| 单击 | 退出预览（用户定版行为，保留） | 退出预览 |

★ **放大后要靠 `userScrollEnabled = false` 把 Pager 关掉**，横向拖动才归"平移图片"。
两个都会抢横向拖动，只在 1x 时让 Pager 接管 —— 这是官方推荐的组合，比拼
`pointerInput` 优先级稳。

★ **单击退出与双击必须用同一个 `detectTapGestures`**（`onTap` + `onDoubleTap`）：
它内部为双击留判定窗口，单击因此**延后约 300ms** 才触发。拆成两个 `pointerInput`
会两边都收到 —— 双击时既放大又退出。
（代价：单击退出会晚 300ms。两个手势共存时无法避免，除非放弃双击。）

其他实现要点：
- `Dialog` 必须 `DialogProperties(usePlatformDefaultWidth = false)`：
  默认弹窗左右留边距，那种宽度下 Pager 翻页很局促、图也看不全。
- 缩放/平移用 **`graphicsLayer`**（绘制阶段生效、不触发布局），缩放才跟手。
- 平移**夹紧**在 `(scale-1)*尺寸/2` 内 —— 不夹的话放大后能把图拖到屏幕外，只剩黑底。
- **每张图各自一份缩放状态**（`remember(当前页)`）：换张时是"新图、新的 1x"，
  不把上一张的放大倍数带过去（带着的话用户会看到新图莫名是放大的）。
- 页码指示只在多张时出现（一张时"1/1"是废话）。
- 选中**复用**列表/网格的同一份多选状态（`selecting` / `selected` / `toggle`），
  并且在预览里选中时**同时置 `selecting = true`** —— 不然回到列表看不到勾选框、
  底部"开始传输(n)"也不出现，用户会以为没选上。
