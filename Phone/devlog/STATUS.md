- **FILL 轴只在 14/30 个图标上有效**（官方原版同样如此），名单在 `MsIcon.supportsFill`，
  核对脚本 `tools/check_icon_axes.py`。
改完先看渲染对照图再装机：`python tools/render_icons.py` → `devlog/icon-sheet.png`。

## 架构

```
ptpip/PtpCodec           线格式（8 字节小端头；操作码/响应码/对象种类常量）
ptpip/PtpIpClient        控制连接：Init 握手 → 直接进控制循环（无认证/无会话密钥）
ptpip/PairingClient      配对流程（PAIR_BEGIN 报设备名 / PAIR_EXCHANGE 交 6 位码）
ptpip/DataChannel        文件端口：DATA_OPEN + 明文数据帧落盘（区间回调零拷贝）
ptpip/ObjectRepository   目录/对象/配对/设备信息的统一出口（单线程 ioExecutor 串行）
ptpip/Discovery          UDP 探测（协议端口候选一次全打；已知地址快扫 + 静默早退）
core/ConnectionCenter    未连接→扫描中→已连接；强制配对；3s 心跳（电量+镜头一个包）
core/ConnectionService  连接保活前台服务（防 MIUI 后台冻结/限网断连）
data/ThumbStore          缩略图管线：内存 Lru + 按相机分目录磁盘缓存 + 数量回收
data/DeviceStore         设备信息（型号/序列号/固件/地区/Java API 版本/安卓版本+SDK/
                         SD 总量与已用/镜头/电量/模式/SSID/IP）；同 guid 合并时
                         "空/未知则保留旧值"——实时字段与固定信息同一条规矩
transfer/                TransferItem/Store（.part 续传，按相机归属）+ DownloadService
                         + StorageSinks（SAF DocSink / FileSink 双通道）
ui/                      单 Activity：未连接页（扫描+配对码输入）/ 主界面 / 文件（列表+网格、
                         全屏预览、长按多选）/ 传输 / 设置（已配对相机、目录、调色盘、关于）
                         / 相机详情（相机卡点进来，字段名左值右的规格表）
```

## 已完成（2026-09-19）：控制中心展开/收起动画（按参考视频 1:1 复刻）

见 `devlog/2026-09-19-控制中心展开动画.md`。用户给了一段参考录屏 + 两张截图，
要求把右下角圆钮**打开悬浮面板**的过程做成视频里那套效果，连续给了五轮验收意见。

- [x] **几何按 density=3.0 反推真值**（第一版按"占屏宽比例"折算，全偏大）：
      用两个已知 Material 尺寸独立印证 density —— 圆钮 168px÷56dp(FAB)=3.00、
      行距 213px÷72dp(ListItem)=2.96 ⟹ 参考图那块屏是 **400dp 宽**。
      真值：圆钮 **56dp**、药丸 **254×55dp**、间距 **13.3dp**、行边距 38.7dp、
      面板圆角 **30dp**。
      ★ 关键认识：**dp 是与屏幕无关的绝对尺寸**，"完全一样"= 照搬 dp 而不是比例
      ★ 我们只有 360dp 宽（参考 400dp），装不下时**药丸与圆钮尺寸一个不动**、
        边距改自适应（`coerceIn(8dp,39dp)`）—— 否则 Compose 会把固定尺寸子项压扁，
        圆钮变椭圆（实测截图）
- [x] **动画三层叠加**（逐帧量参考）：① 按钮**飞上去**（整块按 `1-p` 平移回按钮角）
      ② 原位**由虚到实、由小到大**冒出**深色**新图标（中段还有一段空档，那正是
      "旧的已经走了、新的还没来"）③ 形状**正圆 → 圆角矩形**（`DiscShape` 自定义
      `Outline`，先宽高同步长高、再单独撑宽 —— 否则 1.29:1 的面板会长成横椭圆）
- [x] **过冲用阻尼弹簧解析解当 easing**（试错三轮才定）：
      ① 库的 `defaultSpatialSpec` 实测**根本不过冲**（逐帧量宽度单调收敛）；
      ② 自叠"生长 + 脉冲"两段 ⟹ 用户报**顿挫**（速度从最大瞬间掉到零，C¹ 断裂）；
      ③ 最终改用欠阻尼二阶系统阶跃响应 `x(t)=1−e^(−ζωt)[cos+…]`，
      ζ=0.667 ⟹ 过冲 **6%**、C∞ 连续、不可能顿挫。**必须归一化**（解析解在 t=1
      是 0.99869，不归一化会让静止态永久停在 0.9987）
- [x] **用户报的四个具体问题**（都是我的实现错）：
      ① "没有过冲" —— `coerceIn` 把弹簧的超调裁掉了；
      ② "灰底冲出框外" —— 过冲做进了 `createOutline`（轮廓长出布局盒），
         改到 `graphicsLayer` 的 `scaleX/scaleY`（缩放是绘制阶段的事，天然可超边界）；
      ③ "收起的过冲仍然没有" —— `if (p<=0||p>=1) return 0f` 硬截断把收起方向吃掉了，
         改成用 `overshootNorm`（−1..+1）**同一份来源**驱动面板缩放与按钮位移；
      ④ "文字颤抖" —— 逐帧按缩放比重栅格化文字，加 `CompositingStrategy.Offscreen`；
      ⑤ "收起时向上弹" —— `overshootNorm` 是有号量（收起 −1），直接交给 `translationY`
         （正值朝下）就变成向上。而按钮是被落下的面板**砸中**的，方向只该朝下；
      ⑥ "展开时按钮不该过冲" —— 判据看 progress 超出的**符号**：>0 是展开（按钮不动）、
         <0 是收起（按钮下沉再弹回），只取负的一半，不需要额外方向参数；
      ⑦ 按钮回弹放慢（幅度曲线加 `pow(0.65)` 时间重映射）、面板过冲 6% → **4.5%**；
      ⑧ 原位新图标**不参与过冲**（夹到 1.0，另加 smoothstep 求"丝滑的出现"）；
      ⑨ 曲线趋势在两种之间摇摆过一次，**结论定在慢-快-慢**（用户："改回原来的慢快慢，
         但是变化要稍微明显一些"）—— 主体用 `easeInOutQuart + A·sin²(πt³)`，
         峰值速度 **4.00**（比更早那版阻尼弹簧的 3.54 再陡 13%）；

         展开 400ms（最初 380 / 太慢那版 520）、收起 250ms（220 / 360），
         导航栏 280/180ms；

## 已知边界

- 手机与相机必须同网段（热点/Direct 模式天然满足）。
- 发现分两段：已知地址（配对表 + 网关 + 本机）短窗口快扫 → 未命中才整段 /24 补扫。
  自动扫描命中即停；手动「扫描设备」不早退（否则第二台相机永远看不见）。
- 缩略图是手机按需经文件端口拉取 + 相机端预取缓存；相机预取只在连接建立后开始。
- 缩略图磁盘缓存按相机 GUID 分目录并限量回收（小图 600 / 大图 60），换相机不会串图。
- 批次缩略图上限 200 个文件（ConnectionCenter.collectImagePaths 上限），超出部分滚动时按需拉取。
- **每个对象一次 TCP 连接**（一次 DATA_OPEN 一个对象）。单文件下载无所谓，但
  400 张缩略图就是 400 次建连 —— 目前没有做文件端口的长连接复用，这是后面
  还可以再挖的一处优化（要动协议，未做）。
- **链路明文**：与相机端一致，见相机端 devlog 的安全影响一节。
