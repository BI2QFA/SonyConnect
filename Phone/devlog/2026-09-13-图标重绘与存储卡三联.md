## 一、存储卡：三个数一行摆完（仍是一屏）

原来那张卡是"一个大号**已用** + 右面一截小字 `共 119.3 GB`"：总容量挤在角落，
**剩余量只能靠进度条去猜**（上一版就是因为 `已用 598 MB / 共 119.3 GB · 剩余 …`
被截成 `剩余 118…` 才把剩余量砍掉的）。用户要求剩余量必须看得见。

做法：改成**三联统计块**（已用 / 剩余 / 总容量），各占 `weight(1f)` 一列，
一行摆完，进度条仍在下面：

```
存储卡
┌────────────────────────────────────────┐
│ 已用          剩余           总容量       │
│ 598 MB       118.8 GB      119.3 GB    │
│ ▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░ │
└────────────────────────────────────────┘
```

- 数值用 `titleMedium`（16sp）**不是** `headlineSmall`（24sp）：`119.3 GB` 在 24sp 下
  有 110dp 宽，而一列只有 97dp（360dp 屏 − 卡片留白 − 卡片内边距，再三等分），
  大号字会被截成 `119.3 G…`，反而读不出容量。
- 高度反而**比原来矮**（一行 标签+数值 ≈ 38dp，原来是大号数值 32dp + 一行小字），
  主界面"一屏不用滑动"这条定版更稳了。装机实测：相机/镜头/存储卡/连接四段
  加断开按钮全部在一屏内（`shots-d/home.png`）。
- 顺带把类注释里"没数据时写 —/连接后读取"的旧说法改成"—"（界面上早已没有
  "连接后读取"字样，注释是漏网的）。

## 二、图标：按 Material Symbols Rounded 的纪律重绘

用户说"有的图标不符合 md3e 图标风格"。逐个数下来，问题分三类：

| 毛病 | 例子 |
|---|---|
| 尖角实心块（MD3E 是圆角/圆头） | `add` 十字、`grid` 四方块、`list` 三条、`stop` 方块、`start` 三角、`trash`、`nav_home`、`nav_files`、`refresh`、`drop` 三角 |
| **一条边一个粗细** | `file_generic`（实心块挖出斜缺口）、`palette_dots`（圆角方框的圈：四角 1、四边 2）、`image_placeholder`/`thumb_download`（实心路径拼框，四边不等宽） |
| 笔画端头是方的 | 所有描边图标（1.7 → **2.0**，与 Material Symbols 24dp、weight 400 的 2 单位一致） |

重绘规则（写新图标照这个来）：

1. **描边图标**：`strokeWidth="2"` + `strokeLineCap/Join="round"`，几何取 24 网格
   （横竖都留 2.5~21.5 的余量）。
2. **实心图标**：所有拐角必须有圆角（显式弧，或"同色 fill + `strokeWidth 1.5` 圆角描边"
   把角磨圆 —— `start`/`arrow_back`/`drop` 用的是后者）。
3. **圆一律写成「直径弦」**：`M cx-r,cy a r,r 0 1,0 2r,0 a r,r 0 1,0 -2r,0 Z`。
   ⚠️ 非直径弦会留下**两个候选圆心**，`large-arc`/`sweep` 选错就画到另一个圆上去 ——
   相机镜头第一版就是这么歪的（镜头环与内孔不同心，看着像一坨）。直径弦没有歧义。
4. `evenOdd` 用来挖洞（房子的门、调色盘的缺口与色点、信息图标的圆环）；
   洞要"实心"就换一条独立 `<path>`。
5. 图标一律 `#FF000000` 或纯白，交给 Compose 的 `Icon(tint=…)` 着色 ——
   `ic_nav_panel` 原来写死 `@android:color/white`，**浅色主题下按钮容器是浅色，
   白图标等于看不见**（现在跟着 `contentColor` 走，装机实测收起态是深色箭头 ✓）。

顺带删掉三个**全工程零引用**的 icons：`ic_battery`、`ic_download`、`ic_sdcard`。

### 为了"能看"而写的工具：`tools/render_icons.py`

图标改完只有装机才知道对不对，一轮 = 一次 Gradle 构建 + 安装。这个脚本用 Pillow
自己做了一遍路径填充/描边（C/Q/A 曲线细分、evenOdd 挖空、圆头圆角），几秒出一张
对照图 `devlog/icon-sheet.png`（深底 + 浅圆片两种底、每个图标带名字）：

```
python tools/render_icons.py                    # 全量
python tools/render_icons.py ic_folder          # 只看某几个
ICON_CELL=200 ICON_COLS=3 python tools/render_icons.py ic_camera   # 放大看细节
```

⚠️ 它不是 Android 渲染器，只支持本工程用到的子集；但**踩出一个真坑**：
第一版把 SVG F.6.5 的圆弧圆心符号写成 `large == sweep`（规范是 `large != sweep`），
于是所有非直径圆弧都画反 —— 唯一的直径弦用例（各种圆形）恰好不受影响，
所以 `refresh` 这种环形箭头在预览里只剩一小段弧。**修的是工具，不是图标。**

## 三、文件页：文件夹图标两次降调

用户先嫌"太扎眼"、再嫌"太大"，两次指向同一件事：**文件夹在文件列表里不该比文件更重**。

| 轮次 | 列表行 | 网格格 |
|---|---|---|
| 原状 | `IconTints.Amber` 圆片（浅黄底 + 深棕字形，深色卡片上一块亮色） | 40dp `primary` 色字形 |
| 第一次（配色） | 中性圆片（`surfaceContainerHighest` + `onSurfaceVariant`） | 56dp 中性方块 + 28dp 字形 |
| **第二次（尺寸，定版）** | **裸字形 28dp**，与"非图片文件"的纸张占位同尺寸同色 | **裸字形 36dp**，与同一视图里的占位块同尺寸同色 |

定版理由是"同视图内同类内容同权重"：列表里图片是 56dp 缩略图、非图片是 28dp 裸字形，
文件夹就跟着 28dp；网格里非图片是 36dp 占位，文件夹就 36dp。文件夹靠**形状**区分，
不靠底色和尺寸。

### 顺手修的真 bug：网格里 `.txt` 显示成照片占位

列表那边一直是 `if (isImage) 占位照片 else 纸张`，网格里漏了这条判断，
一律画"山 + 太阳" —— 一个 `.txt` 在网格里就成了照片图标。现在两边同一条规矩
（装机实测 `TWA KLOG.TXT` 已是纸张图标，`shots-d/files-grid2.png`）。


- 只收**含中文的字面量**：日志 tag / 偏好键 / JSON 字段名都是 ASCII，一次滤干净；
  注释里的中文不算（扫描前状态机先剔注释）；`Log.*` 与**异常参数**（`throw Xxx(...)`）

  ② **`Log.d(` 在字面量的上一行**（参数换行写）—— 只看本行判不出是日志，
     于是往回看 300 字符、找"括号还没闭合的那个调用名"。
