# 2026-09-13 手机端换装 MD3E（Material Design 3 Expressive）

用户给了两张 Google Wallet 设置页的截图当参考（深色、分段卡片、行首彩色圆片、行尾
开关/箭头），要求"仔细看设计特点，然后把我的软件改成这种 md3e 风格，自己改，可以
自己 debug"。这一版就是这件事的记录。

版本：**versionName 1.1 / versionCode 5**（原来是 1.0 / 3；手机上装的已经是 4，
不改 versionCode 会被 `INSTALL_FAILED_VERSION_DOWNGRADE` 拒掉）。

## 一、从参考图里读出来的设计语言（这一版照着这几条摆）

| 特征 | 参考图里的样子 | 我们的落法 |
|---|---|---|
| 分段 | 一个小标题（安全 / 电子邮件 / 卡券）带一张卡片 | `SectionHeader` + `GroupCard`，段间靠留白分 |
| 卡片 | 28dp 大圆角、色调面比页面底亮一档、**不投影** | `surfaceContainer`（页面底 `surface`） |
| 行 | 左圆片 + 标题 + 灰说明；行尾箭头或开关 | `SettingsRow` / `IconCircle` / `Chevron` |
| 圆片 | 淡紫/淡绿/淡蓝/淡橙/淡粉，深色字形 | `IconTints` 六个固定色（**故意不跟主题色相**，否则一行行图标全同色，反而分不出用途） |
| 开关 | 大药丸 + 里面一个对号 | `Switch(thumbContent = 对号)` |
| 分隔线 | 从文字起笔处开始，不顶到卡片边 | `RowDivider(startIndent = 76dp)` |
| 顶栏 | 返回箭头 + 大标题 + 副标题 | `AppHeader`（自己排，见下） |
| 排版 | 标题比基线 MD3 更"站得住" | headline/title 四档上 W600 |

## 二、material3 1.4.0 的现实：**expressive 的组件和主题都拿不到**

三条路都试过，全是 Kotlin `internal`（JVM 签名是 public，反编译看得到，Kotlin 侧
一律编译不过）：

- `MaterialExpressiveTheme` —— internal
- `MotionScheme`（接口本身）—— internal
- `MaterialTheme(…, motionScheme, …)` 这个重载 —— internal
- `ExperimentalMaterial3ExpressiveApi` —— internal

`FloatingToolbar / LoadingIndicator / ButtonGroup / MaterialShapes` 只有 `tokens/` 下的
令牌类，没有实现（`FloatingNav.kt` 里早有同一条记录）。

**所以 MD3E 只能落在两件能落地的事上**：① 视觉语言（形状 / 色调分层 / 排版 / 组件拼法）
全部自己按令牌拼；② 动效在自己写动画的地方照令牌填数。真值已从 aar 的
`tokens/ExpressiveMotionTokens` 字节码常量池读出，抄在 `SonyConnectTheme.kt` 的注释里
备用：spatial fast 0.6/800、default 0.8/380、slow 0.8/200；effects 0.6/3800、0.8/1600、
0.8/800。组件自身的按压/切换动效改不了（material3 内部规格）。

## 三、配色：按色调板整族算，不再只给三个色

原来的 `darkColorScheme(primary=…, secondary=…, tertiary=…)` 只给了三个色，容器色
那一整族（primaryContainer / surfaceContainer* / fixed*）会**落回 material3 内置基线
（出厂紫）**—— 换强调色只换了一处，卡片、药丸、选中行还是紫的，一屏两套色系。

新增 `theme/Palette.kt`：每套种子给三个色相，按 MD3 的 tone 表把每族 0~100 一次算全
（HSL 版，tone 数值与官方令牌对齐；material3 的 `TonalPalette`/HCT 都不对外）。
中性族带一点主色相（彩度 0.05），灰里透出主题色 —— 纯灰在深色下会显脏。

**深浅色默认值改成深色（2）**：参考图就是深色的，没主动改过的用户直接看到深色；
设置里仍可切 跟随系统 / 浅色 / 深色。

## 四、组件套件：`ui/components/Expressive.kt`

`AppHeader / SectionHeader / GroupCard / RowDivider / IconCircle / Chevron / SettingsRow /
SwitchRow / ExpressiveButton / RowIconAction / HintText`。各屏只调用、不各写一套。

新增 10 个矢量图标（`ic_chevron_right / ic_arrow_back / ic_camera / ic_lens / ic_battery /
ic_wifi / ic_add / ic_refresh / ic_trash / ic_info / ic_contrast / ic_palette_dots`）。
相机、镜头、调色盘那几个用 `fillType="evenOdd"` 把内圈挖成空（否则实心一片）。

## 五、逐屏

- **主界面**：改成四段（相机 / 镜头 / 电量 / 连接）。原来是三张等权重卡片居中堆叠，
  看不出主次。未连接时每段写"—/连接后读取"而不是整段消失（版面跳比缺一行更难受）。
  连接段的圆片跟着状态变色：连上=绿、正在连=转圈（占和圆片一样的 44dp 方框）、断开=紫。
- **设置页**：最贴近参考图的一页，五段（文件 / 已配对相机 / 传输 / 外观 / 关于）。
  调色盘与深浅色做成"标签行 + 下面一整条 SegmentedButton"（三个选项挤在行尾放不下）。
  页内的"返回"按钮删了 —— 顶栏已经有返回箭头。
- **传输页**：段落小标题 + 设备副标题（右上角任务菜单）+ 三个计数药丸；**每项任务一张卡**
  （每项自带进度条，卡片把"文件名/状态/进度/字节"框成一件独立的事）。
- **配对页**：说明卡 + 一整颗全宽主按钮（这一页只有一件主要的事）+ 发现列表。
  6 位码输入框改大号等宽居中（要对着相机屏幕核，小字挤在一起最容易看错）。
- **文件页**：路径与动作收进一条 28dp 圆角的药丸工具条；列表行内缩成圆角按压块、
  16dp 圆角缩略图。列表**不套大卡片** —— 一屏十几行套进去，卡片底边会伸到悬浮药丸
  导航底下被压住，四角反而看不出是张卡（试过，不如不套）。
- **悬浮导航**：圆形控制中心按钮的容器从 `secondaryContainer` 换成 `primaryContainer`
  —— 前者是"浅色底"时代挑的（要在一片浅色里跳出来），主题默认深色后它是暗色、沉进底里；
  MD3E 的"主要动作"圆钮本来就是 primaryContainer 那一档。面板里的设备行图标从
  文件夹换成相机。

## 六、装机实测（adb，真机 3d3390a6，720×1640 / 320dpi）

逐屏截图走查，**发现并修掉三处只会在真机上现形的问题**：

1. **浅色下页面底还是黑的** —— Scaffold 的 `containerColor` 我留了透明，页面底实际是
   窗口背景（`themes.xml` 里的深色常量），切浅色后卡片变白、页面底仍是黑的，顶栏
   深色标题直接看不见。改成 `MaterialTheme.colorScheme.surface`。
   深色下它与窗口底同色所以看不出区别 —— 正是这种"只在浅色下才现形"的最容易漏。
   顺带把浅色方案的面调了一档：页面 tone 99（MD3 名义是 98）、卡片 94，装机实测
   98 与 94 只差 4 档几乎分不出卡片边界。
2. **配对页按返回，关掉的是底下的设置页** —— `OnBackPressedDispatcher` 是后进先出，
   我把 `showSettings` 那条注册在 `showPairing` 之后，于是配对页盖在设置页上时，
   先收到返回的是设置。用户看到的现象是"按返回什么都没变"（配对页还在），
   设置却在背后被关掉了。改成 `enabled = showSettings && !showPairing`。
3. **已配对相机行被撑成三行** —— 行首 44dp 圆片 + 行尾垃圾桶吃掉大半宽度，标题列只剩
   约 144dp，"ILCE-6300 SN:05186914 · e0fa60c4"写不下。改成标题只放型号、说明里写
   "SN:xxxx · 设备码 · IP:端口"，并给 `SettingsRow` 的标题加 `maxLines = 1`、
   说明加 `maxLines = 3` 兜底。SN 与设备码都还在（设备码是分辨"同型号同 SN 多条记录"
   的唯一依据，不能丢）。

## 七、验证状态

**真机走查过的**：主界面（连接中 / 失败两态）、设置页（含浅色与深色两套、
已配对相机列表、SegmentedButton、开关、关于）、传输页（真实历史任务：完成态两张卡）、
配对页（无相机时的空态 + 扫描中）、悬浮导航与控制中心面板、顶栏返回箭头、
调试期通过 tap/swipe 走了一遍面板 → 设置 → 配对 → 返回的链路。

**没验证到的**：文件页的**行内容**（缩略图、目录行、网格、多选、FAB）—— 手机上没有
可连的相机（配对表里的 192.168.31.25:15740 连不上，`未找到 ILCE-6300…`），文件列表
拿不到数据。这一页只验证到工具条、面包屑、空态与"未连接"提示的排版；行样式与网格
是 2026-09-13 之后第一次连上相机时需要重点看的地方。

**已知取舍**：
- 已配对相机行不再显示上次的 IP:端口？—— 显示，挪到说明行末尾（会被 `maxLines = 3`
  截断的风险只在极窄屏上）。
- 深浅色默认深色：老用户没动过设置的话，升级后会从浅色变深色。这是有意的（参考图
  就是深色），设置里一次点击可改回。
- 顶栏标题仍是 "SonyConnect" + 相机型号副标题；进设置/配对页时标题换成页名并出现
  返回箭头。没有把主界面标题改成页名 —— 用户之前对"副标题挂型号"这条定过版，
  不动它。

# 同日第二轮：设置改成「分组入口 + 二级页」

用户反馈原话："设置所有设置项不要全都露在外面，要有点进去的二级页面；设置要求全部像
这样；注意观察卡片之间的衔接以及圆角等细节；利用好 md3e 的原生功能。"

## 一、先查了一件决定性的事

`ListItem` 在 material3 1.4.0 里**没有**分组能力：公开签名只有
`headlineContent/supportingContent/leadingContent/trailingContent/colors/tonalElevation/
shadowElevation`，`ListItemDefaults` 也只有单个 `shape`。官方那套
`ListItemDefaults.segmentedShapes(index, count)`（分组列表的原生做法）没进这一版。
所以参考图里"一张卡被切成几段"的观感只能自己按形状拼。

## 二、套件新增（`ui/components/Expressive.kt`）

| 构件 | 作用 |
|---|---|
| `segmentedShape(index, count)` | 组里第 index 段的形状：**外圈 28dp、内圈 4dp** |
| `SettingsGroup` | 组的容器：`verticalArrangement = spacedBy(2.dp)`，组自身上下各 9dp |
| `Segment(index, count, onClick)` | 组里的一段：色调面 + 分段形状 + 整段点击 |
| `SettingsRow(…, index, count, extra)` | 行内容；新增 `extra` 槽挂在行的**下面、同一段里** |
| `GroupCard` | 退化成"只有一段的组"，非行内容（型号/关于/电量）仍用它 |

**衔接与圆角的三个数字**（这是用户点名要看的部分）：

- **组内 2dp**：段与段之间那道缝（参考图实测约 5px@2.25x ≈ 2dp），露出页面底，
  读成"同一张卡被切开"
- **内圈 4dp**：内圈不留直角 —— 直角在深色底上会形成一道锋利的暗边，像被切坏了；
  4dp 就够看着"圆润地收住"
- **组间 18dp**：★ **装机实测踩到**：第一版组间没留白，只有组内那 2dp 缝，结果
  相机/文件/传输/外观/关于五行读成"一长条"，分组等于白分。补上 18dp 之后层次立刻
  立住 —— 层次靠的就是 **2dp 对 18dp** 这一对数字

`RowDivider` 删掉了：分组之后分隔线既不需要、也会和那道缝打架。

## 三、设置的两级结构

`SettingsPage` 枚举 = 页面栈；顶栏标题与返回箭头由 `MainActivity` 按它决定。

一级（`Hub`，五件事件三组，照参考图那版"入口行"）：

```
相机       已配对设备、配对新相机           ›
────────
文件       下载目录、保存位置               ›
传输       传完之后要不要关相机端            ›
────────
外观       莫奈取色、调色盘、深浅色          ›
关于       版本信息、开发者                 ›
```

副标题不是套话：参考图里每一行的副标题都在**列出这一页能改什么**
（"支付方式、交易"／"姓名、邮箱、电话、地址"），照做，用户不用点进去就知道去哪儿找。

二级页五个：`Cameras` / `Files` / `Transfer` / `Appearance` / `About`。
原来平铺在设置页上的开关（自动关闭相机客户端、莫奈取色、调色盘、深浅色）全部搬进
对应的二级页；"调色盘"的色点行与"深浅色"的分段控件靠 `extra` 槽和它们的**标签行同处
一段**（一张卡里的一件事，而不是标签一张卡、控件另一张卡）。

## 四、导航与转场

- 返回键：二级页 → 一级页 → 退出设置（**先退二级**，注册顺序与 `enabled` 条件都按
  "最上面那层先收到返回键"来，见 `MainActivity` 里那段注释 —— 装机时这里踩过一次）
- 从控制中心面板进设置时重置到一级页（不会停在上次那个二级页）
- 从"相机"二级页进配对页，返回时回到**相机二级页**而不是一级页（页码状态不动）
- 转场：顶层页面之间仍是**纯淡入淡出**（用户定版）；一级↔二级之间改用 MD3E 的
  **共享轴 X** —— 进二级页从右推入、返回从左推回，位移只有屏宽的 1/4。方向由两个
  状态的页码算出来（页码藏在页面 key `settings:<n>` 里），所以返回时自动反着播。
  内容按 **key** 取页而不是按外层状态：转场期间新旧两页同时在画，都读外层状态的话
  旧页会跟着变成新页的内容，动画就白做了。

## 五、顺带新增的一处交互

已配对相机的行**整行可点 = 切到那台**（原来只有行尾的垃圾桶能点，行本身是死的）。
理由是这一页每一行都是"进得去"的，留一行点不动会让人以为界面卡了；而且这和悬浮面板
里点设备行的行为一致。为此说明行会写"已连接"或"点这一行切换到这台"。

## 六、这一轮的取舍

- 已配对相机行**不再显示上次的 IP:端口**：行首 44dp 圆片 + 行尾垃圾桶吃掉大半宽度，
  "型号 / SN / 设备码 / IP"四样放不进两行。SN 与设备码保留（设备码是分辨"同型号同 SN
  多条记录"的唯一依据），IP 只是诊断信息、界面上也没有任何地方用它，先让位。
- 二级页底部不铺 `FloatingNavInset` 的留白：设置页里悬浮导航本来就是隐藏的
  （`hasPaired && !showSettings && !pairingScreen`），原来留的那 112dp 是纯空白。

# 同日第三轮：换成 MD3E 的最新库（compose-bom-alpha）

用户问："能不能使用 md3e 的最新支持库文件"。**能，已经换完并装机验证**。

版本：**versionName 1.2 / versionCode 6**（上一轮是 1.1 / vc5）。

## 一、查清楚的事实

- material3 **稳定线仍是 1.4.0**（compose-bom 2026.09.00 里 pin 的就是它）——
  也就是说前两轮"expressive 拿不到"的结论在**稳定通道上没错**
- expressive 只在 **1.5.0-alpha** 里公开，最新 `1.5.0-alpha28`（2026-09-09）
- androidx 另外发布 **`compose-bom-alpha`**，最新 2026.09.00 正好 pin
  material3 1.5.0-alpha28 + foundation/runtime/ui 1.13.0-alpha03，**一整套互相匹配**
  （单独升 material3 会把它和稳定 foundation 混在一起，所以走 alpha BOM 这条路）

改动只有一行：`gradle/libs.versions.toml` 里 `compose-bom` → `compose-bom-alpha`，
版本 2026.09.00。**换完现有代码零改动就编过了**，然后才逐项把自拼的东西还给库。

## 二、还给库的东西

| 曾经自己拼 | 现在的来源 |
|---|---|
| 形状表（含 largeIncreased / extraLargeIncreased） | `MaterialExpressiveTheme` 默认 |
| 字体表（expressive 的加粗标题层） | 同上 |
| 动效令牌（spatial 0.8/380、fast 0.6/800；effects 0.8/1600、0.6/3800…） | `MotionScheme.expressive()` |
| 分组列表的分段形状（外圈 28 / 内圈 4） | `ListItemDefaults.segmentedShapes(index, count)` |
| 分段配色 | `ListItemDefaults.segmentedColors()` |
| 段间距（曾自己量 5px@2.25x = 2dp） | `ListItemDefaults.SegmentedGap` |
| 行的排版与内边距 | 原生 `ListItem` |
| 药丸导航的弹簧（曾抄数值） | `MaterialTheme.motionScheme.fastSpatialSpec / defaultSpatialSpec` |
| 等待态那枚转圈 | `LoadingIndicator`（会变形的多边形） |

`SettingsRow` 现在就是 `ListItem`：行内容进 **`content` 槽**（expressive 那组重载把
主内容叫 `content`，`headlineContent` 只在不带 `shapes` 的老重载里），
`trailingContent` **不带 RowScope**。顺带白拿了 **按下变形**：按下时那一行会从
"内圈 4dp"动画变形成更圆/更方的形状 —— 这是 MD3E 的标志性手感，自拼的 Row 做不出来。

`Segment`（不是行的那种段）也不再自己算形状，改成向库要
`ListItemDefaults.segmentedShapes(index, count).shape` 的静止态，保证与相邻行同形。

## 三、装机踩到的一个坑

**`ListItemDefaults.segmentedColors()` 默认容器色是透明的** —— 分组列表的官方用法是
调用方自己铺一层分组底板，行本身不着色。我们这边的"组"就是每段各画自己那块面，
所以第一版装上去**整页卡片全隐形**，只剩文字浮在页面底上。补上
`.copy(containerColor = surfaceContainer)` 才对。已写进注释。

## 四、代价（必须知道）

- 依赖走的是 **alpha 通道**：material3 1.5.0-alpha28 是 alpha，API 可能变动。
  以后升 BOM 要重新编一遍确认（这次就是零改动编过，但下次未必）
- 想回稳定线：把 `libs.versions.toml` 里 `compose-bom-alpha` 改回 `compose-bom`、
  版本 2026.09.00，然后 `SonyConnectTheme` 换回 `MaterialTheme`、`SettingsRow` 换回
  自拼（历史版本见本文件第二节与 git 之外的 devlog 记录）。**形状/尺寸的数值不用改**
  —— 自拼那套当时就是照令牌抄的

# 同日第四轮：把 MD3E 的弹簧物理铺到交互上

用户要求："在软件里运用 md3e 最新的弹簧物理系统在交互上做一些优雅美观的动画"。
第三轮已经把 `MotionScheme.expressive()` 接进来了，这一轮是**真的把它用到每一处交互**。

## 一、唯一取用点：`ui/theme/Motion.kt`

六个规格（数值来自官方 `ExpressiveMotionTokens`，第三轮起由库提供）：

| | 阻尼 | 刚度 | 用在哪 |
|---|---|---|---|
| `spatialFast` | 0.6 | 800 | 指示药丸滑动、图标 pop、FAB 收起 |
| `spatialDefault` | 0.8 | 380 | 页面前进、面板展开、尺寸变化、进度条 |
| `spatialSlow` | 0.8 | 200 | 整屏级别（暂未用） |
| `effectsFast` | 0.6 | 3800 | 换色、淡出 |
| `effectsDefault` | 0.8 | 1600 | 淡入、交叉淡变 |
| `effectsSlow` | 0.8 | 800 | 大块内容淡变（暂未用） |

**分工是 MD3E 的规矩**：会动的（位置/尺寸/形变）走 spatial，只变明暗/颜色的走 effects。
把颜色交给 spatial 会让换色带回弹、看着像抖；把位移交给 effects 又会发木。

一律写成 `@Composable` 从主题取（`MaterialTheme.motionScheme`），不抄成顶层常量 ——
规格是随主题注入的，写死就脱离库了。

## 三、踩到的两个坑（都记在代码注释里了）

1. **`AnimatedContent` 的 `transitionSpec` 不是 composable 上下文** —— 里面不能调
   `Motion.*`（它要读主题）。编译器报 "@Composable invocations can only happen from
   the context of a @Composable function"。**在 composable 体里先把规格取好，再当普通值
   捕获进 lambda**（`MainActivity` 顶部、`AppHeader` 里都是这个写法）。
2. **展开态颜色一开始用 `tertiaryContainer`，装机发现这套动态配色里 tertiary 是粉色**，
   紫→粉的色相跨太大，按钮像换了个功能。改成 `secondaryContainer`（同族、退一档），
   也正合 MD3E 的意图：面板已经弹在它上方，按钮该把焦点让出去。

## 四、怎么验的

adb 抓**转场中间帧**（点完 0.12~0.14 s 截屏），这是唯一能证明"真的在动"的办法：
- 切 tab 的帧里能看到指示药丸**正跨在两个图标之间**（同时页面在交叉淡变）
- 展开面板的帧里能看到面板**从右下角长出**、按钮**正在换色**

若只截"动完了"的图，写死 tween 和弹簧看起来一模一样 —— 这类改动必须抓中间帧。

## 五、修：底部药丸的高亮错位（用户反馈）

**现象**：用户反馈"下方胶囊里的高亮选中错位了"。

**原因**：第四轮把选中指示从"这项亮一下"改成**滑动药丸**时，位置算式漏了一项 ——
条目是排在 Row 的 `padding(horizontal = 10.dp)` **之内**的，而指示块是 Row 的
**兄弟节点**、从 Box 的起点 x=0 起算，所以 `index × 节距` 少了那 10dp 内边距，
**恒定左偏 10dp**。

**修法**：算式改成 `padH + (itemWidth + gap) × tabIndex`，并把 `padH` / `padV` 抽成
局部常量、Row 与指示块共用 —— 这类"两处各写一遍同一个数"的错，改一处忘另一处必然
再犯。注释里写清了三个数必须与 Row 的排布一致。

**验法（像素级，不靠眼睛）**：把指示块的横向范围与图标的横向范围都从截图里量出来，
比中心点：

| 状态 | 指示块中心 | 图标中心 | 偏差 |
|---|---|---|---|
| 首页 | 149.5 px | 149.5 px | **0.0 px** |
| 文件 | 289.5 px | 289.5 px | **0.0 px** |
| 传输 | 429.5 px | 429.5 px | **0.0 px** |

顺带核实了一个一直记错的数：**这台设备密度是 2.0**（720×1640 / 320dpi），
不是我前几轮一直当成的 2.25。节距 70dp 实测 140px 正好对上（70 × 2.0）。
以后凡是"dp 换 px"的心算，都按 2.0 走。
